The Tap extension is installed.
Now give it a runtime to talk to.

The extension reuses your real browser session — that's the whole point. But it can't act alone: it needs the Tap CLI running on this machine, either spawned by your AI agent over MCP, or started directly in a terminal. Pick the path that matches how you work.

Connect your AI agent

Claude Code · Cursor · Windsurf · Codex · any MCP host

Auto-edit your MCP host config and restart it. The host spawns tap mcp stdio on demand — no daemon to babysit.

$ {{ site.data.cli.install.curl }}
$ tap mcp connect           # auto-detects host, edits config

Then restart your AI agent. The extension badge turns green within 2 seconds of the first MCP call.

Run standalone

no AI agent · just verify the extension works

Start the Tap MCP server directly. Useful to confirm the extension can reach a runtime before wiring up an agent.

$ {{ site.data.cli.install.curl }}
$ {{ site.data.cli.mcp.stdio }}      # keep this terminal open

macOS / Linux. Windows users: read the install script or use npx -y @taprun/cli.

Verify it worked

  1. Click the Tap icon in your Chrome toolbar. Hover for the tooltip.
  2. Disconnected: ! Tap — disconnected  ·  Connected: Tap — connected
  3. If still red after 5 seconds, open the troubleshooting list below.
Still disconnected? Three things to check
  • Port 9333 in use — Tap's daemon listens on 127.0.0.1:9333. Check with lsof -i :9333; if another process holds it, kill or reassign before restarting.
  • MCP host not restarted — Claude Code / Cursor only re-read MCP config on launch. Quit fully (not just close the window) and reopen.
  • Service worker asleep — Chrome MV3 puts background workers to sleep after ~30s idle. Click the extension icon once to wake it; the badge updates within a second of the daemon being reachable.
